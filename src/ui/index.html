快速开始

① 注册竞品：在「总览」页填入竞品名称 + 官网 + 监控页面（逗号分隔），点「注册竞品」。
② 触发分析：在竞品卡片点「分析」，系统自动跑完整流水线（约几分钟）。
③ 看结果：「竞品情报」页查看对比矩阵、销售战卡、调研洞察、告警记录。
④ 定时监控：默认每天 9 点自动监控所有 enabled 竞品（可在「系统」看 schedule）。

流水线原理

monitor 抓取页面 → SHA-256 哈希快筛 → LLM 识别变化（定价/产品/招聘/新闻…）并打严重度。
research 搜索财务/产品/市场/组织线索 → 生成洞察（带置信度 + 影响评估）。
compare 8 维对比矩阵（我方 vs 竞品 0-10 分）。
battlecard 销售战卡（优劣/差异化/异议处理/电梯陈述）。
quality 3 个评审 agent 并行打分（准确性/完整性/销售可用性），聚合后低于阈值自动回 research 重搜。

监控页面怎么选

monitor_urls 比 website 重要——它是真正被哈希对比、检测变化的页面：
· 定价页 /pricing → 检测价格调整
· 招聘页 /careers → 检测扩招信号
· 新品/发售页 → 检测产品动向
单个 URL 抓取失败不中断流水线（逐 URL 容错）。

配置说明（.env）

MYSQL_HOST/PORT/USER/PASSWORD/DATABASE —— 数据库
OUR_PRODUCT_NAME/WEBSITE/POSITIONING/TARGET_MARKET —— 我方画像
AGENT_MODEL —— 分析主模型（默认 claude-opus-5）
DEEPSEEK_API_KEY —— 评审模型（3 评审 agent 用 DeepSeek）
SMTP_HOST/PORT/USER/PASS + ALERT_EMAIL_TO —— 告警邮件
SERPAPI_KEY —— 搜索（无则 demo 桩）
CI_QUALITY_THRESHOLD —— 战卡质检门槛（默认 7）

常见问题

· 分析很慢？ 每个 stage 是一次 LLM 调用，可用多开 worker 加速并行。
· 收不到告警邮件？ 检查 SMTP 配置 + ALERT_EMAIL_TO，或看「竞品情报 → 告警记录」状态。
· 战卡一直回炉？ CI_QUALITY_THRESHOLD 调低，或检查 DEEPSEEK_API_KEY 是否配置。
· 竞品抓取失败？ 大站可能有反爬，把 monitor_urls 换成更开放的页面。
